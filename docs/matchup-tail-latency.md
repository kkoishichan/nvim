# 配对提示与滚轮慢事件

2026-09-18，基于 `d0e7de2` 继续处理滚动时的长停顿。四轮新旧交替对照中，每组 320 个滚轮事件：**超过 100 ms 的事件从 158 个降到 36 个，超过 200 ms 的从 65 个降到 0 个**。P95 从 **290.28 ms 降到 153.72 ms**，四轮分别比较也均有下降。

原有语法颜色、配对范围、匹配跳转、文本对象和键盘滚动动画均保留。自动提示遇到等待处理的新输入时，会结束本次后台搜索，空闲后按原规则重新计算；手动匹配继续完整执行。

## 处理方式

此前慢事件主要表现为输入排队：上一阶段记录中最慢一次约 244 ms，其中约 230 ms 在输入被处理之前。配对提示的 120 ms 延迟只推迟执行，已经开始的同步搜索仍会阻塞后续输入。

本阶段同时减少计算与处理排队：

- 按行复用配对插件用于判断字符串、注释的 Tree-sitter 捕获，避免同一行每检查一个位置就重新运行查询。当前高亮组的可用性和前景色仍实时读取，保持主题切换和首次渲染的行为。
- 将插件两处反复构造 Lua 表达式的调用改为直接调用，保留原参数和返回结果。
- 经源文件校验的插件内部只读函数直接借用配对记录；公开调用仍返回独立副本。读取函数被其他扩展替换时恢复复制。原匹配算法还按严格的行列顺序排除起点，因此内部共享起点记录不会改变匹配候选。
- 自动定时提示检查待处理输入，不消费按键。若有输入排队，则缩短本次剩余搜索预算并退出相应查询；随后恢复原定时器，清除本次未完成搜索记录的光标位置，确保即使只有视口移动也能重新计算。下一次空闲搜索重新使用原预算和范围，不永久降低搜索深度。

提前结束只用于源文件已核验的自动提示回调，不用于手动 `%`、其他匹配跳转和文本对象。提示在输入繁忙时可以推迟到空闲后更新，这是本次明确的调度变化。没有消费、丢弃或合成滚轮事件，也没有关闭动画。

## 缓存与兼容性

位置语法缓存最多保留 4 个 buffer，每个最多 128 行、4,096 条捕获。超限只停止保留结果，不截断查询输出。文本版本、语法树、活动高亮器、查询或迭代函数变化后重算，包含语言注入区域。

缓存只接受已知的文本判断及静态 `set!` 指令；未知自定义谓词和指令沿用原查询。它适配锁定插件使用的高亮器接口，保留原捕获顺序和优先级。配对插件相关源文件升级或函数被其他代码替换后，相应适配器回退到原实现，需重新验证才启用。

关闭或重载时恢复函数并释放缓存；已排队的旧恢复回调失效，不干扰新实例。安装目录中的插件文件没有修改。

## 启动与回归

无界面启动另按 AB/BA 测六轮，分别复用各组磁盘缓存，丢弃首轮。打开该 Python 文件的启动中位数为 346.14 → 342.20 ms，配对差值中位数为 −1.69 ms；空启动为 112.50 → 122.52 ms，配对差值中位数为 +4.59 ms。空启动不加载 vim-matchup，这些小幅波动不作为启动提速结论。计时到 `NVIM STARTED`，不包含 LSP 就绪。

- Python 及另外十种语言，包括 HTML、Markdown 注入区域的捕获顺序、范围和优先级一致。
- 在真实自动提示回调中排入按键：确认不消费输入、不遗留临时光标位置，空闲后完整恢复提示；手动匹配照常执行；旧恢复回调不干扰模块重载。
