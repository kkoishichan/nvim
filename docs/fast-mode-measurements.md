# 运行模式实测与修补验收

2026-09-20，在同一台机器上对完整模式、快速模式和原生 Neovim 进行了两轮交错测量。覆盖 12 个样本，70 个有效编辑会话通过输入数量、重绘和滚轮目标窗口校验；完整模式的密集长行样本未能完成，失败单列。原始逐事件数据见[测量 JSON](fast-mode-measurements.json)。

快速模式保留主题与 Tree-sitter 高亮，通过关闭自动语言分析和附加界面降低开销。完整模式继续保留原有动画及功能。该测试比较的是功能取舍后的成本，不是对等功能下的编辑器比较。

`transformer.py` 的连续输入 p95 为完整模式 14.61 ms、快速模式 2.72 ms；滚轮 p95 为 18.29 / 11.07 ms。收益并不覆盖每个指标：该文件键盘翻页的首次反馈 p95 为 12.38 / 17.84 ms，快速模式本轮更慢。Markdown 的输入收益也较小；长行和大文件的快速模式内存仍分别约 94 / 154 MiB。以下保留这些结果及未完成场景，不预设所有操作都更快。

## 环境与测量方法

- 前 8 个普通语言样本及启动测量使用 `ab24a42`；其余样本使用 `9929f54`，各批开始时工作树干净。后者补充服务归属保护和等待输入队列排空，不更改上述已通过场景的计时端点。各批提交、基准哈希和失败项均保留在 JSON。
- Neovim：NVIM v0.12.5；Linux 7.2.6-arch2-1 x86_64；Ryzen 7 PRO 8840U，约 30 GiB 内存。
- 使用已锁定的本机插件、parser 和语言工具；采用默认 VS Code 主题与独立状态目录，不读取个人偏好。
- 120×36 PTY，模拟 kitty 的终端询问与鼠标协议；没有启动实际 kitty 窗口。
- 启动数值取 Neovim 的 NVIM STARTED 里程碑，每系列先丢弃一轮，再取两轮中位数。冷/热指 Lua 编译缓存，不清空系统文件缓存；热缓存同时复用配置路径与缓存路径。
- 每个编辑会话先等待 2 秒；这段固定等待不算启动时间。随后测首次输入、30 个连续字符（间隔 25 ms）、2 次保存、2 组滚轮（每组最多 20 个事件，间隔 8 ms）与半页翻动（间隔 80 ms）。短文件按长度减少翻动次数。
- 输入和滚动数值是按键解码到首次反映变化的重绘结束；包括高亮和相关编辑工作，不含解码前排队、kitty 绘制、触控板驱动或网络传输，也不表示完整动画播放时长。
- 表中输入、滚轮、保存和翻页 p95 合并两轮的真实事件计算；首次输入取两轮中位数。首次输入包含首次进入插入模式的懒加载，单独列出。每个样本只有两轮，结果不是长期统计。
- 所有修改和保存均在独立副本；真实 transformer.py 仅复制文件自身，不克隆项目环境，因此诊断数量可能不同于实际项目。Rust 生成样例配有独立、无外部依赖的 Cargo 清单。npm/Cargo 使用离线设置。
- 原生对照使用 Neovim -u NONE、原生语法、行号等必要显示选项，没有 Tree-sitter 或其他插件。所有会话禁用 swap 与 ShaDa，以免恢复文件影响比较；磁盘数值不含这两类数据。

复现命令（输出目录必须尚不存在）：

```sh
python3 scripts/benchmark-mode.py \
  --output /tmp/nvim-mode-recheck \
  --file ~/Projects/transformer/transformer.py \
  --runs 2 --startup-cache both --typing-chars 30 --saves 2 \
  --wheel-bursts 2 --paging-events 6 --fast-lsp-sample diagnostics --keep-going
```

## 内存、后台工作与缓存

内存是编辑结束后 Neovim 与全部子进程的 RSS 合计（包括 Neovim 自带的 TUI 辅助进程），取两轮中位数；RSS 会重复计入共享页，不等于独占物理内存。缓存为每个独立冷会话产生的文件逻辑大小。

大量诊断 Python 的快速模式 RSS/缓存是在显式开启 BasedPyright 后采集，其他快速会话未开启 LSP。所有 24 个快速会话在手动操作前均为 0 个 LSP、0 个活动定时器、0 个文件监听和 0 个语言工具进程句柄；未手动开 LSP 的会话在编辑后仍满足这一点。进程清单中的 nvim 是其自带 TUI，不是后台语言工具。

状态目录、工作目录和缓存分别记录在 JSON 的 disk 中；工作目录包含样本与 Rust 构建产物。这些是短会话采样，不是长期缓存增长预测，也不包含共享插件、parser、Mason 安装体积。切换模式不会卸载完整模式已有资产或删除恢复数据。新服务器默认快速安装是 8 个插件、13 个 parser；显式安装语言/检查工具才额外准备 Mason。

## 修补验收与边界

- 持久化开关：空格 u f、:FastModeToggle 或 :FastMode on|off|auto；保存到 preferences.json，重启生效。验证了重启恢复、连续切换、其他偏好保留、只读目录和坏 JSON；NVIM_MODE 仍有最高优先级。
- 修复精简部署的 Mason 安装器缺失、fast 切回 full 遗留默认值、Java/Rust 手动服务缺失、停止后异步服务仍启动，以及原生搜索中路径转义、忽略规则和同步扫描的问题。
- 修复基准改写原文件、插入文本残留、内部模拟按键重复计数、缺少帧被记作成功，以及滚轮落在浮窗上的问题。原始 transformer.py 的 SHA-256 与测量前一致。
- 默认 29 组回归全部通过；随后补充的工具缺失处理通过 static、mode、languages、toolchain 检查；基准完整性回归 2 项通过。独立快速环境离线准备了 9 个含安装器的锁定插件并复用 4 个检查工具。
- Java/Rust 快速入口在独立临时项目中启动真实 `jdtls` / `rust_analyzer`，均完成初始化、响应文档符号请求并停止。过程中没有加载 JDTLS/Rustacean 完整集成或 Blink；结果保存在 JSON 的 `manual_lsp_smoke`。另有回归验证停止命令不会关掉借用的外部客户端。
- 真实 SSH/tmux 网络会话、kitty 像素呈现和触控板硬件未实测。SSH 环境变量检查只证明 auto 选择逻辑。本机短测不承诺不同服务器、工程或连接上的固定延迟。

完整终端记录、逐次启动日志和窗口事件证据分别位于 `/tmp/nvim-fast-mode-final-matrix`、`/tmp/nvim-fast-mode-final-rest` 和 `/tmp/nvim-fast-mode-long-fast`；真实手动服务证据位于 `/tmp/nvim-fast-manual-tusfy0d5`。这些目录属于可清理的临时验收数据。仓库中的 JSON 保留输入哈希、配置/锁/基准哈希、逐事件延迟、全部有效会话摘要及失败记录。
