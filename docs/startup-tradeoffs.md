# 启动优化复核

2026-09-18，基于 `3275351` 检查运行时优化的启动代价。**撤除 Python 高亮谓词缓存，恢复原生查询**。原有语法颜色、字体、配对提示和 Neoscroll 键盘动画继续保留；配对结果缓存、位置语法缓存和自动搜索让行继续启用。

此前每个进程首次打开 Python 都要读取、解析、改写并额外编译高亮查询。在最新配对优化基础上，这层缓存仅使普通滚动事件的中位耗时减少约 1.5 ms，编辑操作对减少约 1 ms；本次撤除后，滚动 P95 反而更低。结合首次打开的成本，选择移除实现及专用检查组，减少初始化工作和维护代码。

## 启动

同机 Neovim 0.12.5、相同安装资产及锁文件，基线包含工作区原有的 SQL 配置修改。每个场景七轮 AB/BA 交错，丢弃首轮，以下为六次有效样本的中位数，单位 ms。状态、日志与编译缓存使用临时目录。

| 场景 | 撤除前 | 撤除后 | 配对差值中位数 |
| --- | ---: | ---: | ---: |
| 打开 transformer.py，复用编译缓存 | 204.39 | 195.41 | −12.85 |
| 打开 transformer.py，每次新建编译缓存 | 279.29 | 244.73 | −33.54 |
| 空启动，复用编译缓存 | 103.92 | 104.48 | −2.47 |
| 小型 Lua 文件，复用编译缓存 | 281.73 | 284.78 | −17.49 |

Python 启动的两组中位数分别减少约 9 ms、35 ms。首批筛选测量为 207.28 → 183.67 ms，说明绝对耗时及差值有明显波动，不将初测约 24 ms 当作固定收益。空启动和 Lua 不经过被移除的入口，作为波动对照，不声称它们加速。配对差值的中位数与两组中位数相减不等价。

计时到无界面模式的 `NVIM STARTED`，不包含首屏显示或 LSP 就绪。新建缓存只清空每轮 Neovim 编译缓存，没有清空操作系统文件缓存。

同时检查了另外两项策略：

- **faster.nvim 宏优化保留**：暖缓存下模块读取、配置及 after/plugin 合计约 1 ms；改成首次按 `@` 加载没有测出稳定启动收益，暂不改变宏入口。
- **Lua 回收步进设置保留**：恢复原倍率没有测出启动改善；本次不把运行时收益已经验证过的设置一起撤销。

配对适配器在文件启动时初始化约 5 ms，含约 1 ms 的调用桥准备；此前对滚动长停顿的收益较大，继续保留，见[慢事件处理](matchup-tail-latency.md)。这些初始化计时只用于归因，与完整启动对照分开采集。

## 滚动与编辑的取舍

只读打开原项目 `~/Projects/transformer/transformer.py`，240 行、10,706 字节。basedpyright、ruff、typos_lsp 全部初始化，诊断为零。源文件 SHA-256 始终为 `0b139ed3dede0a953bb37ae1467b146b32e5095532794608096ec3a014bb3afb`。

滚动测量使用冻结副本，一份保留全部现有优化，另一份仅撤除 Python 缓存启用入口。四轮 AB/BA，每轮四段双向滚动，每段 20 个 SGR 输入，间隔 8 ms；每份配置共 320 个事件。PTY 使用 `xterm-kitty`、120 × 36，等待 LSP 8 秒，准备后再等 700 ms。

| 指标 | 撤除前 | 撤除后 |
| --- | ---: | ---: |
| 滚轮事件中位数 | 6.15 ms | 7.68 ms |
| 滚轮事件 P95 | 42.58 ms | 34.78 ms |
| 滚轮事件 P99 | 68.13 ms | 56.69 ms |
| 最大事件耗时 | 70.30 ms | 72.56 ms |
| 超过 50 ms 的事件 | 12 / 320 | 5 / 320 |
| 插入、删除及两次重绘中位数 | 30.29 ms | 31.33 ms |
| 插入、删除及两次重绘 P95 | 92.74 ms | 93.90 ms |

逐轮滚动 P95 为 `31.04 / 42.58 / 28.59 / 47.01` → `25.91 / 44.87 / 24.24 / 23.77` ms。普通事件有小幅代价，尾部延迟没有稳定退化；并非撤除后每项运行时指标都更快。

编辑对照另用两个 AB/BA 轮次，每轮执行 100 次在第 70 行末尾插入、删除字符的操作对，并各重绘一次；剔除每轮前十次，每次之间留 8 ms 处理界面输出。全部修改只在临时进程的缓冲区内进行，不保存文件。这是同步编辑及重绘成本，不等于物理打字、补全或 LSP 响应时间。

滚动计时包含终端输入解码和 Neovim 装饰绘制，不包含真实 kitty GPU、桌面合成器、显示器及输入设备。短划内事件互相排队，不能当作独立样本；本页只比较本批数据，不与历史不同环境的绝对延迟混用。
