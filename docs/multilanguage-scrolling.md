# 多语言滚动对照

当前高亮谓词缓存仍只默认启用 Python。此前的原生滚轮路径、滚动条刷新合并、状态栏缓存和垃圾回收调整由各语言共用；颜色预览的刷新合并适用于启用了颜色预览的文件。本次没有修改日常运行时配置、主题、高亮、诊断或键盘动画。

## 为什么没有直接推广缓存

扫描了配置中的 43 个解析器，另对 Lua、C、C++、Go、Java、JavaScript、TypeScript、TSX、Rust 九种语言试验缓存。同一语言中，缓存后的捕获名称、范围和元数据与原查询一致，编辑后的失效、跨语言切换及共享容量淘汰也通过检查。C++、TS/TSX 的继承查询继续保留。

查询本身算得更快，并不保证完整滚动更快。缓存也保留了额外对象，且每种语言首次启用都要准备查询。查询探针中，额外准备时间约为 Lua 6.6 ms、Go 3.7 ms、Java 9.0 ms、JS 41.9 ms、TS 66.2 ms、Rust 108.7 ms、C++ 170.1 ms；这是单次查询准备测量，不是完整启动耗时的可靠估计。

以下是完整配置的终端输入对照。单位为 ms，每格为“原查询 → 缓存查询”。不同轮次的方案分开记录，避免只保留有利结果。

| 语言与轮次 | 事件中位数 | 事件 P95 | 判断 |
| --- | ---: | ---: | --- |
| Lua，初步两轮 | 6.57 → 5.71 | 50.92 → 23.76 | 初步看起来有收益 |
| Lua，四轮复测 | 6.67 → 9.65 | 53.23 → 53.88 | 未复现初步收益 |
| Lua，等待 8 秒后两轮 | 7.86 → 13.31 | 65.63 → 52.34 | 普通事件变慢，不能视为全面改善 |
| Go，初步两轮 | 11.49 → 8.58 | 65.70 → 58.29 | 初步有收益 |
| Go，等待 8 秒后两轮 | 10.46 → 13.74 | 76.67 → 78.98 | 未复现初步收益 |
| JavaScript，两轮 | 7.28 → 10.77 | 63.37 → 54.90 | 指标变化混合 |
| TypeScript，两轮 | 6.44 → 6.02 | 17.97 → 37.65 | 长停顿增加 |
| TSX，两轮 | 6.37 → 7.53 | 49.53 → 56.44 | 两项都变慢 |
| Rust，两轮 | 3.65 → 4.06 | 27.48 → 15.66 | 中位数变慢，停止滚动的最大延迟从 23.33 升至 63.44 |
| C，两轮 | 9.14 → 19.78 | 114.04 → 93.33 | 指标变化混合 |

这些是有限样本的探索性结果，不代表整个语言的固定速度。Rust 来自本机项目中的 `movement.rs`，Lua 使用上一版缓存模块的冻结副本；C、Go、JS、TS 使用已安装插件中的本地源码/测试文件；C++、Java、TSX 使用生成样例。每种语言一个文件，不能据此推断所有项目。完整文件路径、校验值、原始事件延迟和分轮数据见 [测量记录](multilanguage-scrolling-results.json)。

C++ 最初的对照暴露了测量脚本的问题，未计入有效速度对照：诊断虚拟行使一个滚轮事件不再等于三行源代码，反向滚动还可能在最后一个事件之前到达文件顶部。Java 完整测试先遇到隔离环境的工作区写入问题，隔离生成目录后仍有 JDTLS 退出和原生 Java 文件类型清理留下的错误状态，因此也未给出速度结论。它们的查询一致性检查已通过，但不能据此宣称实际滚动更快。

最终选择保留原处理方式。上述数据不足以支持为其他语言默认增加查询编译和缓存开销。

## 保留的测量改进

`scripts/benchmark-wheel-pty.py` 继续使用 `xterm-kitty` 和真实 SGR 鼠标输入，记录输入写入到 Neovim 装饰重绘的时间，仍不包含物理设备、kitty GPU、合成器或显示器延迟。

- 通过只读的解码事件计数与视口重绘配对，不再假定每次滚动必定移动三行源代码。
- 记录虚拟行和折行偏移，保留诊断、折行与折叠功能。
- 每次把光标定位到第 10 行或第 90 行，再分别向下或向上测量；保留 `scrolloff`，实际窗口顶行由原配置决定。要求至少 140 行，避免把文件边界处没有移动的事件当成慢帧。
- 语言服务生成的工作区写入本轮临时目录，安装好的插件、解析器和工具继续复用。
- 可设置等待时间，并记录各轮语言服务是否初始化、待处理请求数和缓存状态；状态观察不会启用原本未启用的其他语言缓存。

最终脚本已用带诊断虚拟行的 C++ 样例和原 `transformer.py` 检查输入、双向滚动、动画映射、高亮启用状态及源文件未修改。协议修正前后的数据不能直接合并。本页保留旧协议下通过全部断言的数据，用于解释为何拒绝推广缓存；新版脚本用于后续测量。

```sh
python3 scripts/benchmark-wheel-pty.py --file /path/to/code.rs \
  --baseline /path/to/baseline-checkout --runs 4 --bursts 4 --settle-ms 8000
```

用于隔离试验的[候选补丁](multilanguage-predicate-experiment.patch)基于 `f6028e8`，未应用到日常配置；它包含多语言查询准备及九语言一致性检查，供在单独 checkout 中复跑。原始试验的观察方式、轮数、等待时间与失败原因均记录在 JSON 中。

补丁使用零行上下文保存，在 `f6028e8` 的隔离 checkout 中应用时使用 `git apply --unidiff-zero /path/to/multilanguage-predicate-experiment.patch`，随后运行 `./scripts/check.sh treesitter_predicates`。该实验已在独立副本中通过一致性检查。
