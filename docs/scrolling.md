# 鼠标滚动验证

本轮针对普通代码中的滚轮、触控板滚动卡顿，以 `421c451` 为基线。前一轮编辑与 UI 微基准未涵盖真实颜色插件在 `WinScrolled` 中的全部工作，因此新增完整 Neovim 屏幕网格测量和真实终端鼠标协议检查。

## 已确认原因与修复

Neoscroll 仅接管分页和定位快捷键，不接管滚轮；Snacks 的滚动动画已关闭。本轮保留鼠标原生输入及键盘动画配置，也保留滚动条的折叠位置计算和鼠标拖动。

锁定版本的 nvim-highlight-colors 每次滚动都会同步扫描可见代码，并对已附着的语言客户端重复调用 `vim.version()`。本机采样中，`vim.version()` 内部的 API 元数据读取占约 21% 的样本，普通代码即使没有颜色字面量也会执行。逐项隔离时，关闭颜色插件比关闭滚动条、括号匹配或缩进装饰带来的改善更明显。

颜色背景模式还会在相同位置重复新增高亮标记：22 行可见颜色重复刷新十次，标记数量从 22 增至 242；清理后恢复为 22。CSS 变量解析有额外的全文查找成本，因此不能把每次滚动等同于一次轻量装饰操作。

新的颜色预览适配层将视口刷新合并到 50 ms 的时间窗中，正文先响应滚动，再更新颜色。连续滚动也会定期刷新，结束后显示新区域的颜色。每批先清除旧高亮，再绘制各个实际可见范围，避免同步字面量高亮重复累积，并正确处理鼠标滚动非当前分屏和同一文件的多个视口。文本变化的原有刷新入口与手动开关继续保留。

该适配针对当前锁定插件：通过 Neovim 公共自动事件接口识别其回调，只替换滚动和尺寸变化入口。插件的可见范围辅助函数仅在同步绘制期间临时适配，完成或出错后恢复，不修改 Neovim 全局 API 或已安装插件文件。升级依赖后需要重新运行 `scrolling_colors` 检查。

语言服务的颜色请求在每批中按缓冲区合并，不因多个分屏重复请求全文。上游对跨批次迟到的 `documentColor` 回复仍缺少版本过滤，异步回复可能重复添加高亮；本轮未改写其 LSP 处理器，不能据此宣称所有 LSP 色块都已去重。普通 Lua 测量仅附着不支持该请求的 `typos_lsp`，不受此异步边界影响。

## 本机验证结果

2026-09-15，Neovim 0.12.5，120 × 36 屏幕，完整配置和相同锁定依赖。每场景为 3,000 行 Lua，每份配置两轮、每轮 80 个滚动事件，按 AB/BA 顺序执行；剔除每轮前十个事件后，每份配置每场景保留 140 个样本。P95 使用 nearest-rank 算法。

| 场景 | 原配置中位数 | 修复后中位数 | 原配置 P95 | 修复后 P95 |
| --- | ---: | ---: | ---: | ---: |
| 普通代码 | 6.05 ms | 3.70 ms | 27.17 ms | 19.86 ms |
| 含颜色字面量的代码 | 6.02 ms | 3.99 ms | 26.70 ms | 19.72 ms |

普通代码首帧中位延迟下降约 39%，含颜色代码下降约 34%。后一个场景滚动结束时，原配置两轮均留下 46 个色块标记；修复后均为 1 个，对应最终可见范围中的颜色。以上为受控重绘测量，不能直接换算成物理触控板延迟或实际终端帧率。

22 组快速回归全部通过。新增检查验证 40 个连续滚动回调不执行同步颜色扫描，随后只扫描一次；同时验证分离视口的标记范围、即时编辑更新、手动开关、错误恢复、重载和卸载清理。

真实 PTY 的 SGR 鼠标检查也通过：向下、向上和非当前分屏均正确滚动，焦点与另一窗口位置保持稳定，新可见行均显示颜色。所有快照无 Neovim 错误，滚轮始终未加载 Neoscroll。

原始样本、终端快照及探针摘要保存于 [scrolling-results.json](scrolling-results.json)。

## 复跑

```sh
./scripts/check.sh scrolling_colors
python3 scripts/scroll-smoke.py --output /tmp/nvim-scroll-terminal
python3 scripts/benchmark-scroll.py --baseline /path/to/baseline --output /tmp/nvim-scroll-comparison
```

`scroll-smoke.py` 使用真实 PTY 和 SGR 鼠标协议验证向上、向下及非当前分屏滚动，并检查颜色是否覆盖新区域。

`benchmark-scroll.py` 需要 Python msgpack，加载完整配置及真实插件，通过原生鼠标输入测量视口移动后的第一帧 UI 刷新。两份配置按轮次交错运行，剔除每轮最初十个事件；事件间在上一帧完成后留 8 ms 处理时间。它是受控的滚动重绘测试，包含本地 RPC 开销，不代表固定频率的触控板连续输入，也不包含真实终端、桌面合成器或物理设备延迟。
