# 快速模式设计

状态：已实现并完成验收修补，2026-09-20。初始设计基于 `main` 的 `37000af`；修补包括持久化开关、手动语言服务生命周期、精简工具安装、原生搜索和基准数据完整性。本文记录运行模式、功能取舍、服务器部署和验收边界；实测结果及限制见[运行模式实测](fast-mode-measurements.md)，用法见 README 的「运行模式」和[部署文档](deployment.md)的「精简部署」。

独立的 `fast` 启动模式保留熟悉的编辑方式、主题和 Tree-sitter 语法高亮，默认关闭自动语言分析与附加界面刷新。完整模式 `full` 继续保留现有功能，包括键盘滚动动画。快速模式同时配套精简安装，适合 SSH、容器及资源有限的服务器。

## 现状与收益来源

原入口先加载所有核心模块，再由 Lazy 导入整个 `user.plugins`。只在插件配置末尾隐藏界面，仍可能留下依赖加载、初始化代码、自动命令和后台服务。现在入口先选择模式和功能集合，再加载对应模块与插件配置。

主要需要减少的是打开文件、输入、移动光标和滚动时触发的自动工作：LSP、补全与签名、配对范围查找、折叠计算、引用高亮、缩进装饰、Git 标记及多个界面组件刷新。DAP、测试、AI 和部分预览已经按需加载，将它们排除出服务器安装主要减少依赖和磁盘占用，其收益应单独统计。

外部文件变更的连续轮询默认关闭，Mason 也不会随普通文件打开而安装工具，这两项已有行为继续保留。快速模式还关闭了首次缺少 Lazy 时的自动下载、Lazy 的缺失插件安装和配置变更检测，以及 Oil 打开目录后的文件监听。

设计时的本机目录占用快照如下，来自目录实际占用统计，数字经过取整，不能作为精简模式的预计体积：

| 类别 | 当前占用 | 意义 |
| --- | ---: | --- |
| `~/.cache/nvim` | 9.5 MiB | 其中 Lua 编译缓存约 8.7 MiB，有助于启动。 |
| `~/.local/state/nvim` | 8.0 MiB | 混合保存日志、撤销、交换文件和历史；撤销约 4.4 MiB。 |
| `~/.local/share/nvim` | 2.5 GiB | 主要是已安装资产：Mason 约 2.0 GiB、插件约 268 MiB、parser 等约 74 MiB。 |

运行模式控制计算与新文件的产生；精简部署控制新服务器上安装多少东西。已有完整安装切到快速模式时，磁盘上的完整模式资产继续保留。

## 启动与切换

持久化开关为 `<leader>uf`（空格、u、f）或 `:FastModeToggle`。也可使用
`:FastMode on`、`:FastMode off`、`:FastMode auto` 明确选择；不带参数的 `:FastMode`
等同切换。设置写入 `preferences.json` 后自动原地重启；切换以当前运行模式为准。
有未保存修改时显示原生确认框，取消会保留当前进程和已保存的选择，再次切换可重试。
重启恢复文件、标签页、分屏和光标位置；不恢复旧模式的选项、插件映射及终端任务。
有运行中的终端任务时先确认是否停止，默认取消；取消后任务继续运行。
目标模式已生效时只保存选择；无 UI 的 headless 会话只保存并提示手动重启。
写入保留其他偏好，配置不可写或 JSON 损坏时报告失败且不重启。

临时覆盖单次启动：

```sh
NVIM_MODE=fast nvim path/to/file.py
NVIM_MODE=full nvim path/to/file.py
```

`preferences.json` 增加 `runtime.mode`，可设为 `full`、`fast` 或 `auto`。显式环境变量优先，其次是主机偏好，未配置时仍用 `full`。`auto` 只是选择规则：检测到非空 `SSH_CONNECTION` 或 `SSH_TTY` 时选择 `fast`，否则选择 `full`。服务器部署写入 `fast`，因此进入 tmux 后即使 SSH 环境信息丢失也不改变默认选择。

不依赖 `TERM=...kitty` 判断机器性能、是否远程或能否显示图片；容器也可显式选择快速模式。非法模式值给出一次配置提示，并回退到有效主机偏好或 `full`。

模式在启动时确定。交互切换通过原地重启生效，避免在同一进程中尝试卸载插件、回收全部映射和重建语言客户端。原生状态栏显示 `FAST`；`:ModeInfo` 按需显示当前模式与选择来源、已保存的默认值、能力降级原因、手动开启的语言服务和存储路径。启动时环境变量优先；交互切换会清除重启子进程继承的 `NVIM_MODE`，让用户刚保存的选择生效，父 shell 的环境变量不受影响。普通启动不递归统计缓存。

## 功能取舍

| 功能 | 快速模式默认行为 | 收益与代价 |
| --- | --- | --- |
| 主题与语法高亮 | 复用当前主题和相同 Tree-sitter parser/query，保留已有 Python 缩进修复。 | 保持源码可读性；接受解析器本身的计算成本，不通过重写高亮规则提速。 |
| 基础编辑 | 保留现有保存、窗口、搜索、quickfix、原生注释、撤销及常用移动键。保留局部字符判断的自动括号；surround 等操作按键加载。 | 日常编辑习惯变化较小。mini.nvim 只初始化选中的模块。 |
| Leader 提示 | 保留 which-key，按空格后显示当前模式可用的快捷键；普通和可视模式都支持。使用 ASCII 按键标签，不加载图标提供者，关闭原生命令的额外提示。 | 保留快捷键发现；接受 which-key 自带的模式检测和按键等待开销。 |
| LSP | 默认不启动任何客户端，也不做工具版本探测。 | 去掉后台分析、诊断和逐次编辑通信；默认没有类型诊断、跨文件语义跳转及重命名。 |
| 补全与函数签名 | 不加载 Blink 及片段库；使用原生手动单词、路径和命令行补全。 | 输入时不自动扫描候选或请求签名；没有自动候选菜单和参数提示。 |
| 检查与格式化 | 关闭自动 lint、保存时格式化和自动拼写检查；已有格式化工具可通过显式命令调用。 | 输入、保存不等待外部检查；需要主动检查和整理格式。 |
| Git | 不加载 Gitsigns、不运行 blame、diff 监听或 Git 状态栏刷新；保留终端中的 Git 操作。 | 移除持续 Git 工作；编辑区没有修改标记和实时 blame。 |
| 配对与代码装饰 | 关闭 vim-matchup、illuminate、缩进线、上下文固定行、颜色预览、TODO 扫描和自动冲突扫描。 | 减少光标移动、文本变化和重绘时的查询；保留原生 `%` 与手动文本搜索。 |
| 折叠 | 使用原生手动折叠，关闭 UFO 及自动折叠提供者。 | 不在编辑后重算结构；折叠范围由用户创建。 |
| 状态栏与边栏 | 原生简洁状态栏，只显示模式、文件、修改标记和位置；原生行号，无 Lua 逐行 Git 栏。关闭 bufferline、dropbar、scrollview、Edgy、dashboard 和通知动画。 | 减少重绘和组件联动；缓冲区、目录及符号通过显式操作查看。 |
| 滚动 | 保持原生鼠标滚轮和触控板事件；快速模式中的键盘翻页也直接移动。 | 无动画帧开销。键盘动画的变化单独测量，滚轮收益来自减少滚动期间的工作。 |
| 文件浏览 | Oil 按需打开，保留目录编辑确认和中性灰辅助文字；关闭监听、图标与默认元数据列，仅显示名称，手动刷新。关闭 Neo-tree。 | 保留轻量目录工作流；权限、大小和时间需要显式查看。 |
| 文件搜索 | fzf-lua 按键加载，无图标，预览默认关闭；搜索范围限当前项目，遵守忽略规则。 | 搜索期间才创建进程，减少预览解析；缺少 fzf/rg/fd 时提供原生打开、补全及 quickfix 搜索入口。 |
| 终端、构建 | 使用原生 `:terminal`、`:make` 和 quickfix，构建仅显式触发。 | 继续支持服务器工作；无终端管理、任务面板和测试自动发现。 |
| 扩展工作流 | 排除 DAP、Neotest、AI 集成、图片/PDF、Markdown 渲染、浏览器预览、VimTeX 和桌面输入法集成。 | 减少安装资产及运行依赖；需要完整集成时使用 `full`。 |
| 会话与恢复 | 关闭自动会话保存和 scratch 持久化；保留内存撤销及 swap 崩溃恢复。持久撤销默认关闭，可由主机偏好开启。 | 减少磁盘状态写入；重启后默认无法继续撤销旧修改，swap 仍用于找回未保存内容。 |

`relativenumber` 保留为编辑习惯；默认关闭整行 cursorline 着色。保持现有的大文件保护阈值，不能把普通代码文件强制划为大文件来得到漂亮的测量结果。

高亮承诺针对主题和 Tree-sitter 层。LSP 语义着色依赖语言服务，关闭服务时这部分增强也会消失，不能宣称所有语言都逐像素相同。验收分别比较 Tree-sitter 捕获、配色与语义着色差异。没有安装相应 parser 的服务器使用原生语法和文件类型缩进，并在模式信息中标注降级；打开文件时不下载 parser。

Oil 在缺少系统回收站工具时仍允许浏览和普通编辑；删除操作明确报告不可用，不自动改为永久删除。缺少 Oil 本身时提供原生目录浏览，目录打开入口必须仍可用。

## 按需语言能力

`:FastLspStart [server]` 只为当前缓冲区选择并启动一个已安装的主要语言服务，复用现有工具路径和项目根规则。具有多个候选时显示选择；拼写服务和辅助检查器只在显式点名时启动。语言服务的配置定义与自动启用逻辑已拆开，手动启动不会加载整套 LSP 插件配置。

手动启用后，使用原生 hover、跳转、重命名、手动补全与签名浮窗；仍不开 Blink、自动签名提示、lightbulb、引用高亮和界面进度通知。诊断以手动浮窗或 quickfix 查看，默认不画下划线、虚拟行和实时标记。服务支持时将诊断范围限制到打开文件。

启动 LSP 就会重新引入编辑同步、分析和可能的项目索引开销，隐藏诊断不能取消这些工作。`:FastLspStop` 同时取消尚未完成的选择和启动请求，只撤销本模式管理的缓冲区附着，最后一个受管缓冲区退出后再停止本模式拥有且没有其他使用者的客户端。

缺少可执行文件时提示安装要求，不启动 Mason、不下载 SDK。Java、Rust 的基础服务也走显式入口，不加载会自动启动服务和调试扩展的 JDTLS/Rustacean 集成。Java 需要 JDK 21+，工作区缓存按完整项目路径区分；Rust 默认关闭保存时检查、构建脚本和过程宏。

## 缓存与服务器能力

缓存按用途处理：

| 数据 | 策略 |
| --- | --- |
| Lua 编译缓存 | 保留。快速模式加载的模块更少，新增缓存也随之减少；目录不可写时退回内存执行。无需引入定时清理任务。 |
| Tree-sitter 内存状态 | 保留服务于高亮与缩进的解析树，随缓冲区生命周期释放。 |
| 功能专用缓存 | 通过停用对应功能停止产生 matchup、补全排序、预览 PNG、索引工作区等新数据；保留旧完整模式数据。 |
| ShaDa | 保留少量文件标记与历史，继续禁止寄存器内容落盘；限制条目规模，不以清除历史换取微小启动收益。 |
| swap / undo | 明确作为恢复数据管理，不能归入可随意清除的缓存。持久撤销按主机偏好启用，swap 默认保留。 |
| 插件、parser、Mason、词典 | 属于安装资产；只在精简部署阶段减少安装范围。切换模式不卸载、不清理完整模式的共享资产。 |

服务器默认使用 ASCII 界面符号，无 Nerd Font 要求；终端支持真彩色时沿用当前主题，否则允许颜色能力降级。鼠标可用时保持启用。关闭自动 `unnamedplus` 同步，避免每次复制都触发桌面剪贴板探测或远程通信；支持 OSC 52 的连接可显式复制到系统剪贴板，常规寄存器始终可用，粘贴依赖终端实际能力。

配置与安装数据可只读。可写状态目录应由当前用户拥有，权限为 `0700`；服务器可指定本机磁盘上的状态路径，避免频繁写网络 home。目录选择和可写性检查只做一次。没有可写目录时仍允许编辑，但明确显示磁盘恢复不可用；临时目录方案需标注退出登录或清理后可能失去恢复文件。不得在公共路径使用固定文件名，也不复用其他用户的恢复目录。

正常启动、打开文件、输入及保存都不应触发插件安装、更新检查、SDK 探测或联网。显式搜索、构建和手动语言服务的子进程单独统计。外部文件变更仍按焦点和缓冲区切换检查，保留未保存修改保护；关闭可选连续轮询及目录监听。

最低版本继续为 Neovim 0.12。精简模式不扩展到旧版 API；旧发行版可使用用户目录内的固定版本 Neovim，暂时无法提供该版本时使用独立的原生编辑器应急。

## 实现边界与部署

实现使用以下边界，避免在各个插件里散落环境变量判断：

| 位置 | 责任 |
| --- | --- |
| `lua/user/core/mode.lua` | 在入口最前面确定模式，输出只读能力集合；不加载插件、不探测语言 SDK。 |
| `init.lua`、`core/options.lua`、`core/autocmds.lua`、`core/keymaps.lua` | 将必要编辑行为与可选功能初始化分开；快速模式不注册已关闭功能的事件、映射和定时器。 |
| `user.lazy` 与插件定义 | 只导入选中的纯配置工厂；主题和 Oil 等共有配置复用。不能先执行整套文件，再按插件名字过滤结果。 |
| LSP / 格式化配置 | 将工具定义与自动启动、自动检查、自动格式化分离，供显式操作复用。 |
| `core/buffer_policy.lua` | 保留大文件判断及增量更新；恢复普通文件能力时遵守当前模式，避免重新启用快模式关闭的功能。 |
| `user/health.lua` | 按当前模式检查依赖，未选择的 SDK 不算错误。详细版本探测只在显式健康检查时运行。 |
| 部署、准备、锁验证脚本 | 共用模式的资产选择规则，验证选中插件及传递依赖；完整模式继续验证完整清单。 |

基础安装为 Lazy、当前主题、nvim-treesitter、mini.nvim、which-key、Oil、fzf-lua、Conform 和 nvim-lspconfig，共 9 个插件。编辑和显式工具按需加载相应模块；快速模式不安装其余主题、Blink、预览二进制及整套 Mason 工具。显式选择工具组或准备检查工具时额外准备 Mason 安装器，但它不进入快速模式的运行插件集合。

选择内置 `default` 配色时不需要主题插件，基础集合为 8 个；`default` 始终出现在主题选择器中。

使用现有 Lazy 管理这些插件，关闭自动安装、更新和配置变更检测。Lazy 或可选插件缺失时走不依赖插件管理器的原生编辑入口；显示一次降级说明，详细缺失项留给 `:ModeInfo`。原生入口需要真实验证打开目录、保存、缩进、退出及恢复行为。

共用完整锁文件作为版本来源。快速模式的子集不是清理依据：会改变安装资产或锁文件的管理操作统一进入显式维护流程，以完整清单判断保留项。快速模式不提供会按当前子集执行 `clean/sync/update` 的入口。已有插件路径继续复用，避免通过 `NVIM_APPNAME=nvim-fast` 复制整套数据。

部署参数 `--editor-mode fast` 与 `--profile python/web/...` 分开。`minimal` 只表示语言工具组；仅选择 `minimal` 不会缩减完整模式的插件与 parser。部署为 `fast` 或 `full` 都会保存相应默认模式，保留其他主机偏好。

新服务器选择 `--editor-mode fast` 时，未显式选择工具组就不恢复任何 Mason 工具；基础搜索依赖可选，缺少时使用已说明的原生入口。默认安装 13 个 parser，覆盖 Bash、Lua、Python、JSON、YAML、TOML、Markdown、Vim、Vimdoc、query，以及所需的注入和依赖 parser；其他语言通过部署参数显式加入。保留现有版本锁定、staging 验证和可恢复的配置切换。

运行时不要求编译器、tree-sitter CLI、Node、Python SDK、Java、Rust、ImageMagick、Poppler 或浏览器。构建 parser 仍需要对应构建工具，可在准备机器完成；离线包必须匹配目标系统、架构及 parser ABI，并在目标环境验证可加载性。不能把一台机器上的整个数据目录直接当作跨平台包。

## 阶段与验收

按现有工作方式，每阶段完成验证后单独提交：

1. **模式入口和初始化隔离**：加入模式选择、能力集合、原生入口及状态显示；拆出共用配置。验证默认完整模式行为、模式优先级、缺少 Lazy 和只读目录。
2. **快速编辑与按需工具**：落实上表、Oil/搜索降级、手动格式化及单服务 LSP 生命周期；关闭功能的映射不能成为隐式加载入口。验证 Python 参数冒号缩进、目录切换、保存、停止服务和大文件恢复。
3. **服务器精简部署**：选择插件与 parser 子集，跳过未选工具；锁文件保持不变。验证离线准备、缺少资产、只读配置、无图形/字体/剪贴板环境，以及完整模式资产未被清理。
4. **真实输入测量和回归**：比较完整模式、快速模式与原生 Neovim，形成速度、内存、事件和磁盘增量报告；完整模式继续通过现有检查。

性能验证使用相同 Neovim、文件、窗口尺寸与已准备依赖，交错运行多个样本，分别测空启动、首次打开、首次输入、连续输入、保存、滚轮和键盘翻页。至少覆盖实际 `transformer.py`、Lua、JS/TS、Rust、C/C++、SQL、Markdown、长行及大文件，既测无警告代码，也测大量诊断的场景。

冷、热缓存分开；首次按需操作的成本也单独报告。除中位数外，记录输入及滚动延迟的 p95、超过 50/100 ms 的事件次数、Neovim 与子进程合计内存、活跃客户端、活动轮询/监听，以及新增磁盘文件。目标是可重复降低延迟，尤其减少长停顿；不预先承诺固定毫秒或倍数。

快速模式在没有主动调用工具时，应满足自动 LSP 数量为零、配置引入的后台子进程为零、文件监听为零。保留 which-key 后，接受其原生每 50 ms 一次的模式检测定时器；不增加其他周期轮询。此前测量的零空闲定时器结论属于未启用 which-key 的版本。性能报告同时说明为了保持高亮和编辑正确性而保留的成本。

PTY 测试用于验证 kitty 的滚轮输入与编辑器处理路径，真实 SSH/tmux 测试用于确认远程交互和绘制流量。模拟 SSH 环境变量只能证明选择逻辑，不能替代真实网络测试。原生编辑器对照用于判断剩余延迟是否来自文件读取、终端或连接；不将机器和网络差异归因于配置。
