# vim-matchup 配对查询缓存

后续对输入排队、位置语法检查和自动提示调度的处理见 [滚轮慢事件优化](matchup-tail-latency.md)。

2026-09-17，基于 `e6228c2` 优化配对提示的重复计算。使用同一个 `~/Projects/transformer/transformer.py`，保留三个 LSP、原有语法颜色、配对高亮和键盘滚动动画。四轮新旧对照的滚动响应中位数从 **67.78 ms 降到 11.28 ms**，P95 从 **298.56 ms 降到 205.51 ms**。长停顿缩短，但尚未消除。

## 改动

插件寻找当前位置、前后及周围配对时，会临时移动光标并反复获取相同的 Tree-sitter 捕获。当前搜索范围是上下各 300 行，对这个 240 行文件通常覆盖全文件。`user.core.matchup_cache` 复用相同文本版本、搜索范围、语言区域、查询和语法树下的结果；检查跳过区域时直接复制已计算的小型索引，避免为了查找不存在的跳过标记而重复复制整份配对记录。

返回给插件的配对记录及范围仍是独立对象，保持其身份比较和调用方修改行为。没有改变配对范围、120 ms 显示延迟、周围配对提示、屏外标记、`%` / `g%` / `[%` / `]%` 跳转及 `i%` 文本对象；语法高亮查询和 Neoscroll 配置也没有改动。

缓存最多保留 4 个 buffer，每个不超过 1,024 条记录、65,536 字节捕获文本。编辑、撤销、重做、重新解析、查询替换、搜索范围变化和语言注入区域切换后重新计算；卸载 buffer 时释放缓存。超出容量时继续执行原查询，不截断结果。模块重载会恢复旧实现后重新接管，不叠加回调。

适配器核对锁定版本两个源文件的 SHA-256；插件升级或实现被其他代码替换后，自动沿用插件原实现，需重新验证后才更新适配器。含谓词或指令的查询也沿用原实现，避免缓存依赖外部状态的自定义规则。因此这项优化并非对所有语言都生效，也不能把 Python 的收益推广到其他语言。

## 滚动对照

测试文件 240 行、10,706 字节，SHA-256 为 `0b139ed3dede0a953bb37ae1467b146b32e5095532794608096ec3a014bb3afb`。文件始终只读，内容未变。基线是未加适配器的配置；测试时工作区并行出现的 SQL 配置改动也复制到了临时基线，保持相关运行配置一致。

在真实主机环境运行，要求 basedpyright、ruff、typos_lsp 全部初始化，确认 0 条诊断；等待 8 秒，准备后再等 700 ms。四轮按 AB/BA 交替执行，每轮四段双向滚动，每段 20 个 SGR 滚轮输入，间隔 8 ms。两组各 320 个事件，PTY 为 `xterm-kitty`、120 × 36。性能测试顺序执行，没有同时运行其他测试。

计时从输入写入到 Neovim 视口装饰重绘完成。控制使用独立 RPC 通道，输入解码和可见视口变化分别记录。以下单位均为 ms：

| 配置 | 中位数 | P95 | P99 |
| --- | ---: | ---: | ---: |
| 原配对查询 | 67.78 | 298.56 | 324.60 |
| 配对查询及跳过区域缓存 | 11.28 | 205.51 | 230.82 |

合并中位数下降约 83%，P95 下降约 31%。P95 使用最近秩 `ceil(n × 0.95)`。逐轮 P95 如下，避免只展示合并结果：

| 轮次 | 原配对查询 | 缓存后 |
| --- | ---: | ---: |
| 1 | 280.79 | 219.83 |
| 2 | 241.76 | 212.54 |
| 3 | 258.67 | 79.84 |
| 4 | 324.30 | 166.05 |

640 个事件均通过输入数量、实际视口移动、最终输入完成重绘和源文件未修改检查。每段前后三个 LSP 均初始化且附着，诊断始终为零，诊断变化事件增量也为零。Tree-sitter 高亮和键盘动画映射保持启用；原生滚轮没有加载 Neoscroll。

事件会在每段中互相排队，不能视为独立样本。结果反映这个文件和本轮运行条件，仍有明显波动；约 200 ms 的慢事件说明还有剩余开销。这不是物理滚轮/触控板、kitty GPU、桌面合成器或显示器的延迟，也不是帧率。

## 启动及行为验证

另测六轮 AB/BA 无界面启动，每组使用自己的磁盘缓存并丢弃首轮。空启动中位数为 122.48 → 141.32 ms，打开该 Python 文件为 346.54 → 352.88 ms；配对轮次差值的中位数分别为 +8.40、+1.68 ms。空启动日志中未加载 vim-matchup，因此该组存在与本适配器无关的启动波动。这批数据不支持启动提速，也不用于声称零额外开销；它只测 `NVIM STARTED`，不包含 LSP 就绪时间。

新增 `matchup_cache` 检查组直接对照安装版本的原查询，覆盖：

- 捕获范围、文本、节点，光标移动时复用，调用方修改隔离，以及非空跳过区域。
- 编辑、撤销/重做、解析树失效、查询替换、依赖外部状态的谓词、容量回退。
- Python、Lua、C、C++、JavaScript、TypeScript、Rust、Go、Java、HTML、Markdown 及注入区域的结果一致性。
- 真实配对高亮位置、屏外标记、匹配跳转和文本对象的原版/缓存对照。
- 多 buffer 切换、卸载、反复初始化、模块重载及不兼容实现回退。

最终通过 `static`、`matchup_cache`、`integration`、`treesitter_predicates`、`lifecycle`、`scrolling_colors` 检查。安装资产核验覆盖 83 个锁定插件、43 个解析器版本及 4 个检查工具。
