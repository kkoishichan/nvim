## 阶段一

- F01/F02：读取前的有界成本检查与编辑范围增量检查；保留 filetype 和撤销；共享颜色、补全、格式化、lint、折叠、Treesitter 准入。LSP 根发现与初始化均检查目标 buffer，已附加服务只脱离目标文件。隐藏文件恢复时补回窗口折叠设置。
- F03：五个平台补齐 fzf，并验证最低版本。
- F04/F05：Codex 使用当前精确选区；Claude 使用当前文件/行范围引用。Claude 中断通过公开终端接口发送单次 Escape，不关闭 IDE 服务。依据：[Claude Code 官方快捷键](https://code.claude.com/docs/en/interactive-mode)。测试使用替身传输，没有真实外发。
- F06–F09：Jest/Vitest 按项目识别并提供 `:TestAdapter jest|vitest|auto`；JDTLS 明确使用已验证 JDK；ShellCheck 清除未保存文件旧磁盘诊断并保留 source 语义；Ruff 遵循项目规则。
- 独立检查入口：`./scripts/check.sh [--group] static|integration|performance|ai|languages`，不指定时运行全部。

复测方法与路线图一致，每场景四次，取后三次中位数：空启动 51.5 ms；两行 Lua 152.1 ms；30,012 字节单行 JSON **156.4 ms**（原 6282.8 ms）。这是本机无头启动结果，真实终端延迟留在后续阶段验证。

行为回归包含稀疏长行、粘贴与恢复、隐藏文件折叠恢复、共享 LSP 两文档、延迟 initialize 前变成长行且不发送 didOpen、AI 首次/连续/反向/块/Unicode 选择、JS A→B→A 与 monorepo、Java 21/17 交叉、ShellCheck 编辑/保存/source、Ruff 88/120 项目规则。

## 阶段二

- 共享工作区、语言项目、仓库与实际 cwd；显式选择只影响当前 tab。嵌套仓库不继承外层语言环境，worktree、符号链接和 `..` 保持真实路径含义。
- 搜索与任务使用共享工作区；任务保留模板包级目录，重跑仅限当前工作区；延迟输入捕获操作发起时的项目。
- 普通终端、Codex 和 OpenCode 按项目管理进程。OpenCode 使用独立回环端口，校验实际服务目录，并在异步握手中防止串项目。Claude 保留原生单终端集成，绑定首个项目，阻止从其他项目误发。
- 工具解析返回路径、来源和原因；Node 项目工具优先，Python 目标解释器与 debugpy 宿主独立，Java 选择可追溯。缓存包含环境、根目录和偏好，支持安装事件与 `:ToolsRefresh`。
- `:checkhealth user` 显示来源、版本、缺项及当前 LSP；`preferences.json` 提供经过类型校验的机器偏好。

验证覆盖项目 A/B、多 tab、嵌套仓库、Mason 安装/卸载、PATH 和偏好变化、失效 LSP 命令、终端异常退出、异步换项目取消与精确目标通道。全套 static、integration、performance、ai、languages、projects、project_actions、toolchain、terminals 通过；真实健康检查通过。AI 外发全程使用替身。

## 阶段三

完整证据及准备、复跑入口见 [工作流矩阵](workflow-matrix.md)。三组真实工具检查分别通过；涵盖 Python/JS/TS/Vue、C/C++/Go/Rust、Java/TeX/Typst/PDF。断点均核对实际栈帧文件与行号，测试均包含预期通过和故意失败，没有把适配器注册视为实际支持。

- 修复真实验收揭示的问题：Neotest 新加载适配器同步到解析子进程；Python 测试服从项目解释器；js-debug 使用原生 DAP 服务协议，移除失配桥接插件；源码映射等待就绪。
- Java 测试包 0.45.0 与 JDTLS 1.60.0 的 ASM 范围不兼容。已更新锁定值至实际验证通过的 0.46.0，并通过 Mason 定向恢复本机该单包。原包和链接备份位于 `/tmp/nvim-java-test-backup-irfxyo9c`；其它工具未升级。JDTLS 命令入口检查服务真实能力。
- 新增 `:TaskBuild` / `:TaskRun` / `:TaskTest`，任务失败进入 quickfix；Typst 编译错误解析真实源位置。Typst 预览改为命令加载，普通打开和编译不触发下载。
- 普通保存格式化默认 800 ms；TeX 保存后异步格式化，并验证不会覆盖期间的新编辑。asmfmt 限定于 Go Plan 9 汇编。
- 快速组新增 `workflow_actions`；`check-workflows.sh` 显式运行重型真实检查，依赖准备与检查分离。

本机真实工作流需要允许本地调试端口和调试样例子进程，已在相应执行环境通过。视觉体验、跨系统部署与所有真实项目的编译参数不由这些样例保证，分别留在后两类验收记录中。

## 阶段四

- 签名提示拆分为调用解析、参数选择、渲染与 Blink 适配；内部接口变化时逐级降级。重复 setup、模块重载和旧键位引用不会叠加补丁或保留过期任务。
- 高亮采用具名回调注册与单个主题事件分发器，重载替换旧回调。AI 实现首次操作加载，取消提供方选择不发送内容。
- PDF 入口轻量注册，首次打开才加载实现；按 buffer 和实例管理进程、监听器、计时器与图片。取消后的迟到结果不能覆盖新渲染，临时输出通过原子发布保护。无图形协议或缺少工具时提供文字说明与外部打开入口。
- 新增可重复的启动测量脚本，记录锁文件摘要、输入、每次日志和结果；启动错误会判定失败。

验证包含直接清除模块缓存后重载、非当前 PDF 更新、真实文件监听、取消资源归属、签名降级以及主题回调次数。最终启动测量每项四次、丢弃首轮：空启动 **55.9 ms**、小 Lua **156.6 ms**、长行 JSON **170.4 ms**、大 JSON **157.6 ms**。证据：`/tmp/nvim-benchmark-zh_wsab7/results.json`；AI 首次加载与取消选择约 **2.04 ms**。无头启动指标与真实终端绘制分别记录。

## 阶段五

- 文件关闭统一保留各 tab 的分屏，支持保存、放弃和取消；异步选择或离开 buffer 期间产生的新修改不能被旧选择丢弃。最后一个文件保留空白编辑区。
- 窗口按角色区分，编辑浮窗不再因尺寸小而被 Esc 收起；正文、面板、管理器及插件临时提示共享分类。
- 侧栏和底部面板共享空间，保护正文默认 40×8。真实 Edgy 在 80×24、120×36、180×50 中分别保留 45×13、40×9、72×22；隐藏窗口不终止任务，修改中的面板受到保护。
- 会话保存整个多 tab 工作区，保留 cwd 与项目选择，兼容旧 Persistence 文件；排除终端及预览面板，并保持单一自动保存入口。验证保存失败恢复窗口状态、未保存内容保护及真实子进程存活。
- 真实 PTY 验证保存、调整窗口、终端开关、双 Esc 和 Alt-Space；修复传统终端将 Ctrl-/ 编为 Ctrl-_ 时入口失效。三个尺寸的实际补全菜单出现耗时为 20.5、13.7、11.6 ms；四主题正文及弹窗文本对比度检查通过。

详细范围与复跑入口见 [窗口与会话验收](ui-validation.md)。PTY 使用模拟 SSH 环境变量和无图片协议，未连接真实远程主机；输入法组合、终端字体与所有图形协议不由本轮自动检查保证。

## 阶段六

- 旧集成脚本拆为主题模块，保留原有同进程加载顺序，移除逐项镜像调色常量的冗余断言。默认入口共 18 组：静态、16 个行为组和部署故障组；真实语言和 PTY 分层运行。
- 检查前明确核对插件锁、源码修改、指定 parser 文件及 revision、检查工具收据和 Blink 原生资产。每组使用独立配置、缓存、状态和日志，机器偏好不进入检查；缺失依赖不会自动安装。
- 新增独立准备入口、固定提交的 Lazy bootstrap 和固定版本 CI。准备与检查分开，CI 下载校验官方资源 SHA256；离线检查使用真实 Rust 补全，不伪造发布版本或替换匹配引擎。
- 部署支持配置 ref、精确 Neovim 版本、无副作用计划及语言工具组；先验证暂存配置再备份切换，区分依赖、插件、工具部分完成和词典失败。保留旧配置及未提交修改，冲突时不覆盖新出现的目录。
- 实际暂存区验收发现 Lazy 恢复命令会在部分缓存状态下改写锁文件；部署改为精确检出后仅执行必要构建，核对原锁字节不变。升级时复制机器偏好 JSON，其它个人配置修改保留在备份中。
- 补齐 [部署说明](deployment.md)、[CI 验证](ci-validation.md) 和 [维护指南](maintenance.md)。远端 CI 尚未推送执行；五系统覆盖的是依赖计划和故障模拟，未声称五种系统实机安装均通过。

独立数据目录从锁定源码新编译 43 个显式 parser 及 3 个查询依赖；额外环境实际下载四个检查工具及 Blink 原生库。七种依赖损坏与 bootstrap 失败均明确返回非零，恢复后验证成功。CI 指定的两个官方 Linux 安装包实际下载、SHA256 核对及版本运行通过；使用官方 Neovim 二进制再运行最终 18 组也全部通过。

真实干净暂存链条在 `/tmp/nvim-deploy-real-u_6ceplm` 完成：83 个锁定插件、完整 parser、Blink 资产、Markdown 预编译版本 0.0.10 及 6 个 minimal Mason 包，构建、核验与安装均成功。失败回归涵盖启动错误、构建失败、意外锁改写与偏好保留。该验证没有替换当前用户配置入口。

最终配置启动复测同样每项四次、丢弃首轮：空启动 **57.0 ms**、小 Lua **152.6 ms**、长行 JSON **176.5 ms**、大 JSON **152.8 ms**。日志与结果：`/tmp/nvim-benchmark-ylcifxo6/results.json`。原长行 JSON 基线为 **6282.8 ms**；这些是本机无头测量，不作为任意项目或机器的延迟保证。
