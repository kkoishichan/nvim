# Neovim 全面提升路线图：本轮核验版

日期：2026-09-05；基线提交：`bbf8a69`；本机 Neovim：`0.12.5`。

本轮交付是计划，尚未修改运行配置。已有的 `docs/improvement-plan.md` 保留原样；本文补充独立复测、新发现和调整后的执行顺序。暂按“稳定性 → 编码工作流 → 性能与维护 → 界面细节”安排，常用语言的投入顺序可随后调整。

## 目标与判断

这份配置已经具备完整的 IDE 基础。全面提升应围绕四个结果展开：普通编辑持续流畅；切换项目后工具和上下文正确；测试、调试、AI 操作符合按键含义；升级和部署可以验证、可以恢复。

沿用现有 Lazy、Blink、原生 LSP、Conform、Lint、DAP、Neotest、Overseer、fzf-lua、主题及编辑习惯。先修复有证据的边界问题，再收敛复杂模块。插件替换须有实测收益，整体迁移到其他配置发行版不列入本次路线。

启动测量复用已安装插件和 parser，每次将缓存、状态、日志隔离至临时目录，不读写持久 ShaDa。每个场景启动四次，取后三次中位数；计时结束于 `--startuptime` 的 `NVIM STARTED`。快照在启动命令注册的 200 ms 定时回调中取得。

| 场景 | 四次启动耗时（ms） | 后三次中位数 |
| --- | --- | ---: |
| 空启动 | 47.5 / 51.2 / 50.6 / 49.4 | 50.6 ms |
| 两行 Lua | 172.1 / 163.6 / 169.2 / 167.1 | 167.1 ms |
| 约 2.53 MiB、多行 JSON | 166.9 / 162.7 / 175.5 / 172.5 | 172.5 ms |
| 30,012 字节、单行 JSON | 6529.6 / 6478.8 / 6282.8 / 6068.3 | 6282.8 ms |
| 同一单行 JSON，临时禁用颜色预览 | 142.8 / 144.6 / 157.1 / 164.0 | 157.1 ms |

单行样例为一个 `text` 属性，其值包含 30,000 个 `a`，文件末尾有换行。有效对照通过临时入口向 Lazy 的 spec 追加 `nvim-highlight-colors` 的 `enabled=false`，并确认插件未进入生效清单、模块未加载；仓库配置未改动。多行样例为包含 26,000 个 98 字符字符串的 JSON 数组。

这些是本机当时环境的无头基线，不能替代真实终端的首次绘制、首次补全、LSP 就绪或保存响应测量。后续比较必须使用相同输入、版本和方法。

## 问题清单与证据

“已复现”表示本轮做过隔离行为实验；“代码确认”表示调用或配置关系明确，但未完成整条用户操作链的验证；“待验证”不应写成已发生故障。

| 编号 / 优先级 | 发现与证据 | 提升方向 |
| --- | --- | --- |
| F01 / P0 | **已复现：小文件长行造成秒级卡顿。** `plugins/performance.lua:25` 的 `filesize=0.01` 与锁定 faster.nvim 的 MiB 一位小数取整冲突；30 KB 被算作 0.0。`plugins/editor.lua:28` 只检查标记、行数和总大小。样例 `bigfile=false`，颜色对照从约 6.3 秒降至 157 ms。 | 原始字节与有界行长检测；颜色扫描有独立保护；覆盖编辑后产生的长行。 |
| F02 / P1 | **已复现部分降级失效，跨 buffer 影响待验证。** 2.53 MiB JSON 的 `bigfile=true`、filetype 已清空，快照仍有 `typos_lsp`。faster.nvim 的 LSP 处理调用无参数 `LspStop`；锁定 lspconfig 实现会遍历全局客户端并禁用对应配置。位置：`plugins/performance.lua:1`、`plugins/lsp.lua:457`。 | 在启动和附加前做 buffer 级准入；处理异步竞态；只脱离目标 buffer，保留其他文件的服务。 |

## 分阶段执行

### 阶段一：修复可复现问题，建立行为回归（P0 / P1）

交付 F01–F09 的小步修复，先做长行与颜色扫描保护，再做 buffer 级 LSP 降级。fzf 部署补漏、Ruff 配置优先级、AI 选区和语言边界修复可独立推进。先添加对应行为用例，再调整实现；现有检查继续作为基线。

- 统一高成本 buffer 判定，覆盖文件大小、单条长行、长行稀疏分布、打开后粘贴；检测必须有界，不能为了判断成本再做一次昂贵全量扫描。
- Treesitter、颜色、折叠、补全、lint 和保存格式化共享适用条件；允许功能自身设置更严格限制。
- 降级显示原因并提供恢复入口；普通文本编辑、撤销和另一个正常文件的 LSP 保持可用。
- 分别修复 AI 的选区、interrupt 语义；使用替身测试发送内容和操作分发，避免回归测试产生真实外部消息。
- 修复测试框架跨项目缓存、JDTLS 启动 Java 选择和 ShellCheck 未保存诊断；Ruff 跟随项目配置。

验收门槛：同口径单行 JSON 启动中位数目标低于 250 ms，这是待验证目标；打开大文件后正常 buffer 的服务仍能跳转和补全；AI 首次、连续、反向、字符、整行、块及 Unicode 选区正确；A→B 与 B→A 项目切换均不误选测试框架；Java 环境交叉组合表现明确；已在内存修复的 Shell 问题不会重新发布磁盘旧告警；项目 CLI 和编辑器格式化输出一致。

### 阶段二：统一项目、环境和工具来源（P1）

交付共享项目上下文、工具来源报告和配置健康检查。在现有 ProjectRoot / ProjectPick、`toolchain.lua` 基础上演进。

- 区分仓库根、语言项目根、tab cwd、任务运行目录；支持嵌套项目、monorepo、worktree、单文件、符号链接。
- 搜索、测试、调试、新终端和任务显式获取上下文；已存在进程展示真实所属项目，不暗中改变正在运行的 shell。
- AI 会话按 provider 与项目组合管理；新建、找回旧会话和向会话发送内容采用相同选择规则。
- RestartLast 默认作用于当前项目；跨项目任务提供可识别的显式选择。
- 工具解析返回路径、来源和选择原因。项目本地 Node 工具、Python 解释器优先规则明确，Java/Rust 保留专项策略。
- 缓存纳入项目、环境和偏好，并提供安装完成、环境变化后的刷新。保留现有 `clear_executable_cache()`，补齐调用时机。
- 增加 `:checkhealth user` 或等效入口，显示当前根目录、工具路径/版本、缺失依赖、LSP 与测试框架选择原因。

验收门槛：同一 Neovim 中交替使用两个不同环境项目，搜索、运行、测试、调试、AI 目标都可解释且正确；安装缺失工具后能刷新状态；机器差异通过集中偏好表达。

### 阶段三：验证“编辑—检查—测试—调试”工作流（P1）

交付按真实行为验证的语言支持矩阵。先覆盖有已确认问题的 Python、JS/TS、Java、Shell，再覆盖 C/C++、Go、Rust，文档语言按使用频率安排；这是暂定工程顺序，不代表推断用户使用频率。

| 语言组 | 必验流程 |
| --- | --- |
| Python | 项目虚拟环境、BasedPyright/Ruff、项目规则格式化、pytest 运行、debugpy 断点；区分目标解释器与 debugpy 宿主 |
| JS/TS/Vue | 本地工具和配置发现、Jest/Vitest 归属、monorepo、调试源码映射、Node/浏览器 attach |
| Java | JDTLS 启动 JDK 与项目 JDK 分离、Maven/Gradle 根、JUnit/TestNG、测试调试与项目切换 |
| C/C++、Go、Rust | compile_commands/构建产物、Go 测试与 Delve、Cargo/Clippy 与 codelldb；实际命中断点 |
| Shell、Lua、配置文件 | 内存/磁盘诊断一致、保存格式化、项目规则存在时才启用的检查 |
| Markdown、LaTeX、Typst、媒体 | 预览、构建失败输出、PDF 重新渲染；缺失可选工具和不支持图形协议时的行为 |

用现有 Overseer 补齐常用 build/run/test 入口及失败位置跳转。测量保存阻塞，当前同步格式化上限为 2,000 ms；按工具成本设置策略，手动格式化保留慢任务入口。

验收门槛：矩阵中的“测试/调试支持”必须有真实通过和失败测试、至少一个实际命中的断点，不能只用 adapter 或配置表存在作为完成依据。普通 Assembly 的 asmfmt 当前指向 Go Assembler formatter，须确认适用范围后限制自动格式化；尚未证明它已损坏文件。

### 阶段四：降低维护和升级成本（P1 / P2）

交付职责明确的模块边界与统一资源生命周期。

- 签名提示拆成调用解析、参数/重载选择、渲染、Blink 适配；内部接口集中一处，能力检查失败时回退到普通签名提示，保留现有体验。
- PDF 保留文件与命令注册，渲染、缓存扫描和 watcher 在首次需要时启动；验证取消、退出和资源释放。
- AI 保留轻量按键入口，按需加载复杂实现。测量首次使用成本，避免只把等待从启动移到第一下操作。
- 复用现有 autocmd 生命周期中的 generation 与清理机制；高亮注册改为具名替换，重载后回调数量稳定。
- 工具、语言和功能开关共享必要数据，按行为边界逐步迁移，避免一次性改写所有 plugin spec。

验收门槛：签名嵌套调用、重载、多行参数、snippet、Unicode、窗口缩放通过；模拟插件接口缺失时基本编辑仍可用；反复打开关闭 PDF、切项目、重载配置没有重复回调或残留任务。

加载策略以实测为依据：Lazy 会因 Lua 模块引用自动加载插件，见 [Lazy 加载机制](https://lazy.folke.io/spec/lazy_loading)。当前 nvim-treesitter main 明确不支持懒加载，应保留启动加载和 parser 同步，见 [nvim-treesitter 安装约束](https://github.com/nvim-treesitter/nvim-treesitter#installation)。

### 阶段五：统一窗口、键位和会话体验（P1 修复 / P2 打磨）

交付统一的 buffer 关闭入口、窗口角色、面板尺寸规则和真实终端验收记录。F11/F12 的局部行为修复可提前做，完整界面整理在项目上下文稳定后进行。

- 明确正文、固定面板、临时提示、编辑浮窗、管理器的角色；样式、停靠和关闭共享角色定义，各自负责自己的生命周期。
- 关闭 buffer 保持 split；修改未保存时给出可理解的选择；最后一个文件、多个窗口共用 buffer、固定面板均有定义。
- 在 80×24、120×36、宽屏验证正文最小空间；避免左右栏、终端、诊断同时打开时失去可用编辑区域。
- 统一补全、签名、hover、诊断、picker、通知的颜色语义；沿用现有主题，验证所有现有主题的可读性。
- 核对输入法、Alt 键、Ctrl-/、Ctrl-方向键、snippet、多光标和模式局部映射；`gr` 等前缀冲突先复现再调整。
- 明确会话保存整个工作区还是单项目。现有 persistence 保存整份 session 并按 cwd/分支命名，需要与多 tab 项目规则协调，暂不认定插件本身有故障。
- 真实终端覆盖 SSH、无图片协议、缺少 ImageMagick/poppler 等场景。

验收门槛：常用关闭、切换和恢复操作保持一致；未保存内容可找回；多项目会话恢复后目录和任务归属正确；文档键位与实际映射一致。

### 阶段六：部署、升级与长期验证（基础工作从阶段一开始）

交付分层检查、可重现部署和维护说明。

- 将现有回归按主题分组；优先保留用户行为、异步时序、资源清理和故障边界用例，减少仅镜像颜色常量的断言。
- 最小 CI 运行静态检查和核心无头回归；语言集成、真实 UI、完整工具安装分层执行，明确各层证明的范围。
- CI 使用已验证的 Neovim 版本、插件锁和 parser；依赖准备与测试分开，状态与缓存隔离。
- 部署支持明确的配置 revision / Neovim 版本及计划预览；按语言或功能选择工具，保留当前完整方案。

## 提交顺序与完成标准

建议独立提交顺序：长行/颜色保护 → buffer 级 LSP 准入 → fzf 与文档纠错 → AI 选区/中断 → JS、Java、ShellCheck、Ruff 修复 → 项目与工具上下文 → 语言工作流 → 签名/PDF/AI 模块整理 → 窗口与会话 → 部署恢复与 CI 完善。对应回归随每次改动交付，最小 CI 尽早接入。

每一步说明问题、最终行为、验证证据和恢复方法。涉及同一项目上下文的终端、任务和测试改动按依赖合并推进；互不相关的局部修复可并行。插件升级与行为重构尽量分开提交，方便定位回归。

**首批完成标准**：单行 JSON 不再秒级卡顿；大文件降级不影响正常 buffer；干净环境能使用主搜索器；AI 使用当前选择并执行真正的中断语义；跨项目测试、Java 启动和未保存 Shell 诊断通过专项回归。后续阶段再以完整语言流程、UI 验收和部署恢复作为完成依据。

仍需实施阶段验证：真实终端的首次补全/保存延迟、大文件对另一 buffer 的具体 LSP 影响、全部语言的实际断点、完整跨系统部署。已有检查通过不等于这些场景已通过。
