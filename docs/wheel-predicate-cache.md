# 保留视觉效果的 Python 滚轮优化

本阶段恢复并保留 Neoscroll 键盘动画，原来的主题、Tree-sitter 高亮、上下文、缩进线、折叠和滚动条继续启用。kitty 配置未修改。用于对照的 `6dbda23` 也包含原动画；恢复提交为 `fa20331`。

## 改动

滚动重绘会多次对相同节点执行文本相等、Lua 模式匹配和词表判断。Python 高亮查询中的这三种判断改用有界缓存：文本版本未变、节点范围相同且判断规则相同时，复用文本和布尔结果。其他谓词与全部高亮捕获、范围、优先级、注入语言及绘制方式仍由原生实现处理。

查询文件仍来自现有 runtimepath，包括继承和扩展。使用语法树定位谓词名称，保留注释、字符串和指令；不合并或删除高亮规则。通过 `query.set()` 提供的不同显式查询会保持原状。准备失败则继续使用原高亮。

缓存最多保留四个 buffer，每个最多 1,024 个节点，每个节点最多 16 个判断结果，超过 1 KiB 的文本不缓存。文本版本变化会作废对应 buffer 的缓存；卸载或删除 buffer 时清理。缓存不替换内置谓词，也不修改 Neovim 私有接口。

准备只发生在进程首次启用 Python 高亮时。为识别并保留显式查询，需要先取得原查询，再编译缓存版，因此有一次性的额外开销；后续 Python 文件复用结果。重启后会重新读取查询文件。

## 测量方法

后续[诊断与 LSP 复测](python-lsp-scrolling.md)发现，本页测试所在的沙箱会使 basedpyright 启动后退出；当时只附着 ruff 与 typos_lsp，诊断为零。本页数据只能说明该测试条件下的高亮缓存效果，不能排除正常主机环境中的类型检查、符号高亮请求或大量诊断的成本。

读取原项目中的 `transformer.py`，237 行、10,592 字节，前后文件校验值相同。Neovim 0.12.5，120 × 36 网格，PTY 使用 `xterm-kitty`，每 8 ms 注入一个真实 SGR 鼠标滚轮序列。每轮六次正反向短划，每次二十个事件，每份配置四轮，按 AB/BA 顺序交错，共各 480 个事件。

记录从写入终端输入到 Neovim 完成对应视口的装饰绘制的时间。包括输入解码、完整高亮及插件工作；观察点位于终端输出到达显示器之前。这里没有启动真实 kitty 窗口，不包含其 GPU、显示器、合成器和物理设备延迟，也不是屏幕帧率测量。

动画映射、高亮和源文件未修改状态均由测量脚本确认。滚轮走原生路径，不加载键盘动画插件。最后一个事件的延迟另行记录，避免仅用合并样本掩盖短划停止时的等待。

## 最终结果与代价

下面采用最终代码的四轮完整数据，合并各 480 个事件；分位数取最近秩 `ceil(n × q)`。原始数据中的当前版本为 `fa20331` 加本提交的修改，并记录了两个运行时文件的校验值。

| 指标 | 原配置 | 缓存后 |
| --- | ---: | ---: |
| 滚轮事件中位数 | 5.83 ms | 5.65 ms |
| 滚轮事件 P95 | 47.98 ms | 27.21 ms |
| 滚轮事件 P99 | 62.29 ms | 60.12 ms |
| 滚轮事件最大值 | 68.81 ms | 74.01 ms |
| 短划最后一个事件中位数，各 24 次 | 22.61 ms | 21.12 ms |
| 短划最后一个事件 P95 | 37.53 ms | 60.26 ms |

四轮中每轮的事件 P95 都下降，合并后减少约 43%，支持减少连续滚动中的部分长停顿。普通事件的中位数接近，极端延迟仍然存在，短划停止时的尾部 P95 反而变差，因此不能说所有卡顿都已解决。此前试验中更大的中位数收益未在最终四轮中稳定复现；也不能据此判断真实 kitty 窗口的最终显示流畅度。

额外检查了首次打开和编辑开销：

| 辅助指标 | 原配置 | 缓存后 |
| --- | ---: | ---: |
| 打开该 Python 文件的启动耗时中位数 | 171.12 ms | 196.51 ms |
| 一次插入、删除及两次重绘的中位数 | 4.66 ms | 4.45 ms |
| 一次插入、删除及两次重绘的 P95 | 12.03 ms | 11.03 ms |

启动测试按 AB/BA 顺序各测四次，每组首轮不计入汇总；使用完整配置的启动日志，计时到无界面模式的 `NVIM STARTED` 标记，不代表首屏显示时间。本场景中，每个进程首次打开 Python 增加约 25.4 ms，后续 Python buffer 复用已准备的查询。空文件和其他语言未另行计时。

编辑测试连接 Neovim UI，通过接口在第 70 行末尾插入再删除一个字符，每步强制重绘。各测两轮、每轮一百次，去除每轮前十次；每次之间等待 8 ms 处理 UI 输出。该探针未观察到明显编辑回退，但它不是物理打字、补全弹窗或语言服务的端到端延迟测量。
