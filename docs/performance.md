# 性能验证（2026-09-15）

本轮以 `a3827c1` 为冻结基线，保留原有补全、语言服务、大文件保护与界面行为，优化启动和频繁执行的回调。依赖锁未修改。

## 改动

- 系统/Mason 工具查询不再扫描项目目录；仍按工作目录、PATH、环境变量、Mason 数据目录和偏好区分缓存，并检查缓存中的可执行文件是否仍存在。Node 与 Python 项目工具继续遵守最近包和嵌套仓库边界。
- 项目上下文只在同一次调用内复用目录发现，不跨调用缓存文件系统状态；新增或删除 `.root` 立即生效。
- 文件开销检查记录已发现的超长行位置，普通输入、删除及手动关闭增强功能后按变化行检查。删除已知超长行后重新确认是否还有其它超长行，确保撤销、粘贴、重载与恢复行为正确。
- 冲突高亮合并连续编辑的刷新任务；内容未变化时复用扫描结果，同时继续同步诊断状态。
- 无面板时只扫描一次窗口；稳定尺寸不重复写入。同一文件多分屏只读取一次 Git hunks，未变化标记不重复写入；Git 更新复用一个定时器。
- Oil 在目录、命令、快捷键或目录会话入口加载。保留原文件与光标、隐藏目录缓冲区和分屏命令的行为。

## 测量口径

同机 Neovim 0.12.5、相同已安装依赖，串行运行基线与当前配置。每次使用临时 config/cache/state/log，保留全部输入、日志和 JSON，禁止自动安装插件。汇总原始数据保存在 [performance-results.json](performance-results.json)。

启动使用 `--startuptime` 的 `NVIM STARTED` 时间，每场景六次、丢弃首轮、取其余五次中位数。先完成整份基线、再测当前版本的初次结果出现时段波动：连未修改的主题和 faster 模块耗时也翻倍。因此增加同场景逐轮 AB/BA 交错复测，两份配置使用相同输入文件，保留各轮配对差值和初次原始结果。cold 指每次使用新的 Neovim 编译缓存，并未清空操作系统磁盘缓存；warm 指同场景复用首轮生成的编译缓存。启动结果不代表 LSP 已就绪或首屏已经绘制。

运行时脚本加载被测核心模块，覆盖项目查询、三种文件规模的普通/超长行/手动关闭/冲突编辑，以及粘贴恢复。编辑场景记录 300 次“输入再删除”操作对的耗时与 API 次数，包含计数包装本身的开销。UI 微基准使用真实窗口 API，但 Git hunks 和 statuscolumn 下层渲染器采用固定替身，隔离自定义回调成本；不包括 Git 子进程和终端绘制。以上数字不能当作完整按键到屏幕延迟。

真实 PTY 另行检查 80×24、120×36、180×50 的保存、调整分屏、终端切换、Alt-Space 和实际补全菜单。单次菜单观测仅作功能冒烟，不作为性能统计。

## 启动结果

以下为交错复测的各配置中位数，单位毫秒；每个数字来自五个有效样本。

| 场景 | 新缓存：基线 → 优化后 | 复用缓存：基线 → 优化后 |
| --- | ---: | ---: |
| 空白启动 | 70.5 → 67.3 | 70.2 → 70.6 |
| 小型 Lua 文件 | 258.7 → 244.2 | 216.5 → 165.4 |
| 2500 行 Lua 文件 | 262.9 → 244.8 | 211.8 → 183.5 |
| 超长行 JSON | 266.0 → 232.0 | 183.9 → 182.4 |
| 约 2.6 MiB JSON | 265.3 → 241.9 | 186.2 → 173.7 |

文件启动整体改善，小型 Lua 的复用缓存启动约减少 24%，2500 行 Lua 约减少 13%。空白启动和超长行 JSON 的复用缓存结果接近，不声称这些场景显著提速。各场景只有五个有效样本，仍有调度与缓存波动；单轮配对差值的中位数和“两组中位数之差”并不相同，两者均保存在原始 JSON 中。

## 运行时结果

7500 行样例，每个场景 300 对操作。下表为每对操作的中位数，单位毫秒，含同步核心回调与计数包装，不含屏幕绘制。

| 编辑场景 | 基线 | 优化后 |
| --- | ---: | ---: |
| 普通文本 | 0.0326 | 0.0318 |
| 含稀疏超长行 | 19.3983 | 0.0319 |
| 手动关闭增强功能 | 19.9153 | 0.0194 |
| 含合并冲突 | 0.0218 | 0.0188 |
| 粘贴超长行再恢复 | 9.8876 | 0.3072 |

超长行场景的 300 对操作累计从 5863.4 ms 降至 11.7 ms，offset 查询从 8,976,600 次降至 600 次。普通编辑原本已很轻，收益主要来自消除退化场景；不能把超长行的提升倍数套用到所有文件。冲突场景的刷新任务分配由 301 次降至 2 次，全文扫描仍在合并后的任务中完成。

下表为对应回调的中位开销，单位微秒。项目和 UI 场景均六轮、弃首轮后取中位数。

| 回调场景 | 基线 | 优化后 |
| --- | ---: | ---: |
| PATH 工具缓存命中 | 617.6 | 11.5 |
| 项目上下文查询 | 664.7 | 412.1 |
| 项目工具缓存命中 | 663.5 | 418.4 |
| 无面板、单正文窗口 | 21.2 | 3.4 |
| 四正文分屏、六浮窗 | 118.1 | 18.4 |
| Git 概览，同文件双视图、1000 处变更行 | 182.9 | 16.5 |

无面板窗口枚举由 3 次降至 1 次；同文件双视图的 Git hunks 读取由 2 次降至 1 次，未变标记的变量写入由 6 次降至 0 次。连续执行 20 次稳定的管理器布局检查，窗口尺寸写入由 20 次降至 0 次。

三个尺寸的真实 PTY 检查在基线和新配置均通过。新配置的三次补全菜单观测约 10.9、12.6、12.5 ms，支持首次输入路径可用，不足以证明补全算法本身加速。

## 回归与复跑

默认 `./scripts/check.sh` 的 21 组全部通过，包括新增 `editing_cost`、`ui_runtime`、`startup_loading`。其中目录加载覆盖九个独立进程，编辑覆盖实际撤销/重做、大小阈值转换、重载及冲突诊断恢复。原有共享 LSP 客户端隔离、窗口保护、布局和主题检查仍通过。

交叉审查以完整扫描为参照，额外验证了 3000 次随机插入、删除与替换；发现并修复了冲突扫描缓存跳过诊断同步的问题，相关回归已纳入默认检查。

```sh
# 在仓库内运行；输出目录必须尚不存在。
python3 scripts/benchmark.py --baseline /path/to/baseline --runs 6 --cache cold --output /tmp/startup-comparison
# 日常复用编译缓存的启动：将 --cache cold 换成 --cache warm。
python3 scripts/benchmark-runtime.py --baseline /path/to/baseline --output /tmp/runtime-comparison
python3 scripts/ui-smoke.py --output /tmp/terminal-check
./scripts/check.sh
```

本轮未重新运行全部真实语言 SDK/DAP 端到端矩阵；语言接线、工具选择和共享客户端行为由默认回归覆盖。真实 SSH、终端字体、输入法与语言服务器启动时间不在这些测量范围内。
